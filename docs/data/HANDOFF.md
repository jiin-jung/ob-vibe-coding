# 백엔드 담당자 전달 안내

## 브랜치와 파일 위치

- 작업 브랜치: `chore/inu-data-handoff` (develop 기준)
- 데이터 위치: `docs/data/`
- 통합 대상: `develop`
- 기준: [브랜치 규칙](../BRANCH_CONVENTION.md), [커밋 규칙](../COMMIT_CONVENTION.md)

`docs/data`는 파일 경로로 사용합니다. 문서 작업 브랜치 prefix는 저장소 규칙에 따라 `chore/`입니다. 기존 `docs/data` 브랜치를 삭제하거나 변경하지 않았습니다.

## 빠르게 시작하기

저장소 루트에서 `python docs/data/validate.py`를 실행합니다. 외부 Python 라이브러리는 필요 없습니다. 실제 건수와 조사 상태는 [manifest.json](manifest.json), 필드 설명은 [README.md](README.md)에 있습니다.

1. [출처 목록](data/sources.json)과 [사실 데이터](data/facts.json)를 관리용 영역에 먼저 읽습니다.
2. [학교 공통 감사](reports/inu-data-common-audit.md)와 [전공 감사](reports/inu-data-it-audit.md)의 적용 조건·미확인 항목을 확인합니다.
3. 승인할 항목만 원문과 대조하고 공개합니다. `verified`는 수집 단계 상태이고 서비스 적용 승인이 아닙니다.
4. `approved-rules.json`은 현재 빈 배열입니다. 자연어에 있는 학점·평점 수치를 자동으로 실행 규칙으로 바꾸지 않습니다.

## 현재 서버 구조와 연결

저장소는 Node.js·Hono·TypeScript·SQLite를 사용합니다. 이 변경은 조사 자료 전달만 하며 서버 동작이나 DB 스키마를 바꾸지 않습니다.

| 영역 | 연결할 자료 / 주의점 |
|---|---|
| `backend/src/content.ts` (게임 콘텐츠 구현 시) | 검토한 사실 ID·공식 URL을 사건과 현실 퀘스트에 연결. 가상 연구실은 실제 연구실과 구분 |
| `backend/src/game.ts` (게임 규칙 구현 시) | 승인한 학교 규칙과 별도 게임 단순화를 명시. 사실 JSON의 자연어를 바로 판정에 사용하지 않음 |
| `backend/src/ai.ts` (AI 구현 시) | 검토된 사실만 전달. 연구실·교수·학생·학사제도를 생성하도록 맡기지 않음 |
| DB 및 응답 | 조사 원본 snake_case는 보존 가능. 공개 API 응답 변환 시 프로젝트 camelCase 규칙 준수 |

추가 테이블이나 API는 [README](README.md)의 제안일 뿐 구현/도입 요구가 아닙니다. 원본을 유지하고 필요한 사실만 기존 콘텐츠 구조에 매핑해도 됩니다.

## 기존 문서와의 차이

- `docs/INU_FACTS.md`의 일부 '공식 요약' 또는 '미확인' 항목을 이번 공통 조사에서 원문과 대조했습니다. 기존 문서를 덮어쓰지 않았으며 감사 보고서에서 정정 내용을 확인합니다.
- 공통 자료의 최신 학기 공고와 전공 자료의 상시 교환학생 안내가 중복됩니다. 적용 학기·예외를 확인하고 통합합니다. 단순히 출처가 같다고 같은 주장인 것은 아닙니다.
- 원격 `docs/PLANNING.md`는 1~4학년 4턴·4~8분 기획입니다. 초기 조사 문서의 '8학기·2분'은 과거 제안이며 현재 게임 규칙을 바꾸는 요구가 아닙니다.
- 동아리 개수 등 충돌 항목은 확정 숫자로 노출하지 않습니다. 학교 규칙 조문, 학과별 2026학번 졸업요건, INURF 최신 자격 등은 추가 확인이 필요합니다.

## 갱신 원칙

이 디렉터리는 전달 시점 스냅샷입니다. 후속 조사본은 원본 ID를 유지해서 수정하고, 삭제는 자동 반영하지 않습니다. 출처·조건·예외·검토 상태를 같이 갱신한 뒤 `checksums.json`을 재생성하고 검증합니다. 중복/충돌을 해결한 뒤 별도 커밋으로 운영 콘텐츠를 수정합니다.

## 전달 메시지

> `chore/inu-data-handoff`의 `docs/data/HANDOFF.md`부터 봐줘. 공통/정보기술대학 조사 JSON, 출처, 조건과 예외, 미확인·충돌 항목을 정리했어. 바로 게임 규칙에 넣는 운영 seed는 아니고 검토용 자료야. 검토한 사실부터 기존 content/game/ai 구조에 연결하면 돼. 공개/실행은 기본 비활성이고 실제 건수는 manifest에 있어.
