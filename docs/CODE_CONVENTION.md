# Code Convention

## 1. 기본 문법과 포맷

- TypeScript strict. 들여쓰기 2칸, 큰따옴표, 세미콜론 사용.
- 백엔드는 Node로 바로 실행하므로 `enum`을 쓰지 않고 문자열 유니언과 `as const`를 쓴다.
- 백엔드 내부 import는 `.ts` 확장자까지 적는다.
- 한 파일은 한 영역만 다룬다. 공통 로직은 실제로 두 곳 이상 쓰일 때 분리한다.

## 2. 변수와 메서드

- 변수와 함수는 camelCase, 타입과 컴포넌트는 PascalCase, 상수는 UPPER_SNAKE_CASE.
- 함수 이름은 동사로 시작한다. boolean은 `is`, `has`, `can`으로 시작한다.
- 게임 규칙은 `backend/src/game.ts`의 순수 함수로 작성한다. 시드가 같으면 결과도 같아야 한다.
- 스탯, 성적, 엔딩은 코드가 정하고 AI는 글만 쓴다.

## 3. Hono 작성 규칙

- 입력은 라우트 첫 줄에서 `zod`로 검증한다.
- 플레이 소유자는 `x-run-token`, 로그인 사용자는 세션 쿠키로 서버가 확인한다.
- 점수와 업적은 브라우저 값을 받지 않고 서버가 계산한다.
- 응답 JSON은 camelCase, DB 컬럼은 snake_case를 쓴다.

## 4. 예외, 주석, 로깅

- 사용자에게 보여줄 오류는 `{ error, message }` 형식으로 보낸다. `error`는 snake_case 코드, `message`는 복구 방법을 포함한 한국어.
- 주석은 이유가 코드만으로 드러나지 않을 때만 쓴다. 의도한 단순화에는 `ponytail:` 주석으로 한계를 남긴다.
- AI 호출은 `ai_logs`에 남긴다. 키, 메일, 닉네임은 로그에 넣지 않는다.

## 선정 이유

> 마감이 짧은 대회라 규칙은 실수를 막는 것만 남겼다. 게임 규칙을 순수 함수로 두면 빠르게 테스트하고 균형을 맞출 수 있다.
