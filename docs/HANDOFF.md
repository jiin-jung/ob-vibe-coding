# 인수인계

기준: 2026-11-06 13:55, 브랜치 `feat/game-core`, PR #2 (`develop` 대상, 미머지). 마감 15:00 (발표와 시연 준비 포함). 14:15 이후 기능 추가 금지.

## 서비스

**재수강:** 대학생활의 후회를 입력하고 1학년으로 돌아가, 인천대 규칙 그대로 8학기를 다시 플레이하는 웹 게임. 말투는 학사 시스템 공문체(플레이어는 "귀하"). 결과는 재수강 성적표, 칭호, 엔딩, 업적, 랭킹.

## 사용자 최종 결정 (문서와 다르면 이 목록이 우선)

- 8학기. 지금 몇 학년 몇 학기인지 항상 표시. 플로우는 더 길게
- 킥루(벤치에서 발롱까지)의 흐름을 최대한 비슷하게. 구조만 참고하고 이름, 문구, 그림, 코드는 가져오지 않음
- 시작: 학과, 닉네임, 캐릭터, 후회, 스타일 3종(능력치 합 동일), 집중 능력 최대 2개
- 수강신청 반응 속도 미니게임. 올클, 일부 성공, 우주공강
- 현실 사진 미션과 S3 제거
- AI는 Gemini. 기본 모델 `gemini-3.5-flash-lite`. `gemini-3.8-flash`는 시험에서 40초 시간 초과, `gemini-3.6-flash`는 8.8초와 503을 보임
- 재수강, 졸업 학점, 등록금과 학자금 대출, 아이템, 근로와 알바, 드림이, 연구실 유지
- 업적 희귀도: 전설(대기업 취업, 창업 성공, 과 수석, 학생회장) 80점, 희귀(조기 졸업) 50점
- 학과 3개: 컴퓨터공학부, 인공지능정보통신공학부, 인공지능시스템공학과
- 캐릭터는 남, 여 1종씩. 수치 영향 없음
- 알파메일 콘셉트 없음. 술, 신체 접촉, 외모, 실존 교수와 학생, 실제 회사 이름 금지

## 협업 규칙

- 사용자가 기획 단계라고 하면 코드를 건드리지 말고 빌드를 재촉하지 않는다.
- 노션은 수정하지 않는다. 사용자가 직접 고치니 붙여넣을 내용만 준다.
- `jiin-jung/greeting-chat` 브랜치는 지우지 않는다. 사용자가 그대로 두라고 했다.
- 브랜치와 커밋은 `docs/BRANCH_CONVENTION.md`, `docs/COMMIT_CONVENTION.md`를 따른다. PR은 `develop`으로 올린다.
- 비밀 값은 `.local/.env`에만 있다. 출력하거나 커밋하지 않는다. 사용자가 이미 `GEMINI_API_KEY`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`를 넣었다.
- 레퍼런스는 공개 자료에서 AI 활용이 확인되지 않았다고만 말한다. 없다고 단정하지 않는다.
- 인천대 정보는 `docs/INU_FACTS.md`에 근거가 있는 것만 실제 정보처럼 쓴다.
- 확인한 것과 못 한 것을 구분해 보고한다.

## 남은 일 (우선순위 순)

1. **균형 조정 (`backend/src/game.ts`, `content.ts`):** 지금 너무 쉽다. 무작위 3000판 중 초과 학기 4판, 과 수석 879, 대기업 668, 창업 582로 전설이 흔하다. 8학기로 늘며 이벤트와 성장이 누적됐기 때문이다. 이벤트 효과, 집중 성장치, 엔딩 조건을 조정한다. 목표 예시: 무작위 플레이에서 전설 합계 10% 안팎, 초과 학기 15~25%. 테스트의 시뮬레이션 출력으로 확인한다.
2. **이벤트 추가:** 8학기에 비해 이벤트가 16개라 부족하다. 재학생 소재가 오면 더한다. 효과는 코드, 문장은 AI.
3. **브라우저 전체 점검:** 8학기로 끝까지 플레이. 실제 폰 포함. 킥루처럼 한 학기가 가볍게 느껴지는지 사용자와 확인한다.
4. **문서 갱신:** `docs/PLANNING.md`, `USERFLOW.md`, `SCREENS.md`, `GAME_CONTENT.md`, `DEMO.md`, `PROMPTS.md`, `ARCHITECTURE.md`, `README.md`가 아직 4턴, Claude 기준인 곳이 있다. 8학기, Gemini, 수강신청 미니게임, 스타일과 집중 능력, 탭 구조로 맞춘다.
5. **프롬프트 품질:** Gemini 결과가 설명조로 흐르면 고친다. 고친 과정을 `PROMPT_LOG.md`에 사실대로 남긴다. 후회 원문은 저장하지 않으므로 시험 입력을 직접 넣는다.
6. **시연 준비:** `npm run seed`가 시연 랭킹과 3학년 1학기 시작 플레이 링크를 만든다. 대본은 `docs/DEMO.md`. 발표 시간과 로그 제출 형식은 운영진 확인이 필요하다.
7. **CI:** 사용자에게 물어본 상태. PR에서 테스트와 빌드를 돌리는 파일 하나면 된다.
8. **PR #2 머지:** 합칠지 사용자에게 확인한다.

## 실행

```bash
cd frontend && npm run build
cd ../backend && npm run seed && npm start   # http://<노트북 IP>:8787
node --test src/*.test.ts                     # backend에서
```

서버는 `.local/server.pid` 프로세스로 떠 있을 수 있다. 코드를 바꾸면 재시작한다. `backend/src/ai.ts`의 호출은 Gemini Interactions API이며, 실패하면 샘플 문구로 넘어가고 화면에 표시한다.

## 참고: 킥루에서 확인한 흐름

아바타 → 정보 입력 → 스타일 후보 3개(합 동일) → 집중 능력치 2개 → 요약. 이후 탭(홈, 반응, 시즌, 선수, 기록). 홈에 "확인할 일"(이적 제안, 상점은 시즌당 하나). 시즌 보내기 버튼 → 라운드 진행(건너뛰기) → 결과(능력치 증가, 대회 결과, 언론과 팬 반응) → 가끔 전환점. 재수강은 이 구조를 수강신청, 학기 보내기, 전환점, 익명 게시판 반응으로 옮겼다.
