# 시연과 프롬프트 로그 계획

## 3분 시연 (제안)

실제 발표 시간은 운영진에게 확인한다. 3분은 가정이다.

| 시간 | 화면 | 내용 |
| --- | --- | --- |
| 0:00~0:20 | 첫 화면 | 대학생활을 다시 쓴다면? 심사위원에게 후회를 하나 묻는다. |
| 0:20~0:50 | 회귀 목표 | 입력한 후회로 AI가 목표를 만든다. |
| 0:50~1:20 | 1학년 | AI 이벤트를 보고 함께 고른다. 스탯이 바뀐다. |
| 1:20~2:00 | 현실 퀘스트 | 현장에서 사진을 찍고 AI가 판정한다. 숨겨진 선택지가 열린다. |
| 2:00~2:30 | 엔딩 | 성적표, 칭호, 가상 졸업장을 보여준다. |
| 2:30~3:00 | 프롬프트 로그와 랭킹 | 실패와 개선 과정을 보여주고 학과 대항전 계획으로 마무리한다. |

심사위원의 후회로 회귀 목표까지 보여준 뒤, 2학년까지 미리 진행한 플레이로 넘어간다. 그다음 퀘스트, 3학년, 4학년, 엔딩은 실제로 진행한다. 랭킹은 미리 넣은 시연용 데이터임을 밝힌다.

## 시연 사고 대비

| 사고 | 대처 |
| --- | --- |
| 학교 Wi-Fi 차단 | 핫스팟 사용 |
| AI 지연이나 실패 | 샘플로 진행하고 샘플이라고 표시 |
| 사진 판정 실패 | 재시도 화면을 보여주고 다시 찍음 |
| 메일이 늦음 | 인증해 둔 랭킹 화면을 보여줌 |
| 전체 실패 | 리허설 때 녹화한 영상 재생 |

## 프롬프트 로그

제출 형식은 운영진에게 확인한다. 정해진 형식이 없으면 전체 대화 원본을 보관하고, 선별한 5건을 `PROMPT_LOG.md`에 정리한다. 개인정보와 키는 지우고, 나중에 지어낸 로그는 넣지 않는다.

| 항목 | 내용 |
| --- | --- |
| 시각, 도구 | 언제, 어떤 AI를 썼는지 |
| 목적 | 무엇을 하려 했는지 |
| 프롬프트 | 원문 |
| 결과 | 응답 요약 |
| 판단 | 무엇을 채택하거나 거절했는지와 이유 |
| 연결 | 관련 기능이나 파일 |

### 선별할 5건

| # | 내용 | 심사 항목 |
| --- | --- | --- |
| 1 | 과팅 서비스에서 재수강으로 바꾼 피벗 판단 | 창의력 |
| 2 | Claude와 Codex의 반론으로 8학기를 4턴으로 줄이고 분기를 넣은 과정 | 창의력, AI 활용 |
| 3 | 이벤트 프롬프트의 실패와 개선 | AI 활용 |
| 4 | 사진 판정 프롬프트의 실패와 개선 | AI 활용 |
| 5 | 실제 디버깅 사례 | 완성도 |

## 서비스 내 AI 프롬프트

| 기능 | 입력 | 출력 |
| --- | --- | --- |
| 회귀 목표 | 학과, 후회 | 목표 유형, 목표 문장, 심각한 내용 여부 |
| 학년 이벤트 | 학년, 학과, 목표, 현재 스탯, 지난 선택 | 장면, 선택지 2개와 효과 유형 |
| 선택 결과 | 고른 선택지, 변화한 스탯 | 짧은 결과 장면 |
| 사진 판정 | 퀘스트 설명, 사진 | 통과 여부, 얼굴 여부, 이유 한 문장 |
| 엔딩 | 학과, 목표, 스탯, 성적, 칭호 후보 | 칭호 선택, 엔딩, 현실 다음 행동 |

- 사용자 입력은 지시가 아니라 데이터로 다룬다.
- 성적, 스탯 변화, 분기 해금은 코드가 정한다.
- 호출마다 프롬프트 버전, 입력, 출력, 실패 여부를 저장한다. 닉네임과 메일은 넣지 않는다.
