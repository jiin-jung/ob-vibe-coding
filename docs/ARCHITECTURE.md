# 개발 구조 (재수강 기준 초안)

## 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프론트 | Vite, React, TypeScript (`frontend/`) | 정적 빌드라 배포 위치를 나중에 정할 수 있음 |
| 백엔드 | Node.js, Hono, TypeScript (`backend/`) | API 서버. 빌드 도구 없이 실행 |
| DB | SQLite (`node:sqlite`) | 설치 없음 |
| 사진 | AWS S3 비공개 버킷, `sharp` | 위치 정보 제거, 일주일 Lifecycle 삭제 |
| AI | Claude API (`claude-opus-5-5`) | 목표, 이벤트, 사진 판정, 엔딩 |
| 메일 | Gmail SMTP (`nodemailer`) | 랭킹 등록 인증 |

## 시연과 배포

프론트는 API를 상대 경로 `/api`로 호출한다. 시연은 노트북의 백엔드가 프론트까지 제공하고 같은 네트워크의 폰으로 접속한다. 시간이 남으면 프론트는 S3와 CloudFront, 백엔드는 EC2에 배포한다.

## 화면

| 경로 | 내용 |
| --- | --- |
| `/` | 시작, 닉네임, 학과, 후회 입력 |
| `/play/:id` | 회귀 목표, 학년 이벤트, 스탯, 현실 퀘스트 |
| `/result/:id` | 성적표, 칭호, 엔딩, 졸업장, 다시 하기, 랭킹 등록 |
| `/ranking` | 학과별, 개인 랭킹 |

## 데이터

| 테이블 | 주요 필드 |
| --- | --- |
| `runs` | 비밀 토큰 해시, 닉네임, 학과, 후회, 목표 유형, 목표 문장, 학년, 스탯, 퀘스트 상태, 회차 |
| `events` | run_id, 학년, 장면, 선택지와 효과, 고른 선택지, 결과 |
| `photos` | run_id, 퀘스트, 저장 키, 이유, 생성 시각, 삭제 시각 |
| `results` | run_id, 점수, 성적, 칭호, 엔딩, 다음 행동 |
| `users`, `sessions`, `auth_codes` | 선택 로그인과 메일 인증 |
| `achievements` | user_id, run_id, 업적, 점수, 시각. 랭킹은 여기서 합산 |
| `ai_logs` | 기능, 프롬프트 버전, 입력, 출력, 실패 여부 |

게임은 로그인이 없으니 플레이 ID를 추측할 수 없는 값으로 만들고, 비밀 토큰이 있어야 그 플레이를 진행하거나 볼 수 있게 한다.

## 핵심 모듈

| 파일 | 역할 | 테스트 |
| --- | --- | --- |
| `game.ts` | 스탯, 학점, 재수강, 활동, 아이템, 분기, 성적, 업적 순수 함수 | 같은 선택과 시드면 같은 결과, 졸업 판정, 수천 판 시뮬레이션으로 엔딩 분포 확인 |
| `ai.ts` | 기능별 AI 호출, 스키마 검증, 샘플 대체, 로그 | 키가 없을 때 샘플 사용 |
| `email.ts`, `mail.ts`, `s3.ts` | 도메인 확인, 메일, 사진 저장 | 위장 도메인 차단 |

## 이전 코드 처리 (제안)

과팅용으로 만든 커밋 전 코드 중 `email.ts`, `mail.ts`, `s3.ts`, AI 호출과 사진 처리 부분은 재사용하고, 팀, 방, 매칭 코드(`match.ts`, `rooms.ts` 등)는 지운다. `match.ts`는 이미 커밋돼 있어 지우면 Git 기록에는 남는다.

## 시간이 부족할 때 줄이는 순서

1. 사전 로그인과 업적별 순위판
2. 졸업장 이미지 저장
3. 학년별 결과 장면의 AI 생성

후회 맞춤 AI 이벤트, 현실 퀘스트 분기, 성적표는 유지한다.

## 사용자가 준비할 것

`.local/.env`에 직접 넣는다. 채팅에는 붙여넣지 않는다.

- `ANTHROPIC_API_KEY`
- `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET`
- `GMAIL_USER`, `GMAIL_APP_PASSWORD`
- 권한은 해당 버킷의 객체 읽기, 쓰기, 삭제로만 제한하고, 버킷에 7일 만료 Lifecycle 규칙을 설정한다.
